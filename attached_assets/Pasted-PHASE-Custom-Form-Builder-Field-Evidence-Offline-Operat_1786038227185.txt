PHASE: Custom Form Builder, Field Evidence, Offline Operations, Customer Portals, and Pilot Deployment Readiness

Objective:

Prepare Redline for use by a real contractor during a controlled pilot.

The application must support different companies, utilities, contracts, and paperwork requirements without requiring custom code for every customer.

Build a company-configurable form and documentation system that allows administrators to recreate their existing paperwork, connect those forms to work packages and billing rules, collect reliable field evidence, and securely share approved information with customers.

This phase must also improve:

- Offline field reliability
- Photo and document evidence
- GPS and timestamp verification
- Digital signatures
- Custom forms
- Customer-specific submission packages
- Crew onboarding
- Pilot administration
- Data import and export
- Production monitoring
- Security and auditability

Do not remove, replace, or break existing:

- Authentication
- Company onboarding
- Company isolation
- Users and roles
- Crews
- Projects
- Daily reports
- Labor entries
- Equipment entries
- Materials
- Work-package templates
- Charge sheets
- Billing rules
- Missing-charge detection
- Undercharge detection
- Approvals
- Production tracking
- Job costing
- Invoice preparation
- Change orders
- T&M tickets
- Audit history
- Existing database records

Before implementation:

1. Inspect the entire repository.
2. Review the current database schema and migrations.
3. Identify existing form, report, photo, signature, and document models.
4. Extend existing systems rather than duplicating them.
5. Run all current tests.
6. Record existing failures.
7. Fix blocking bugs before adding new functionality.
8. Create safe backward-compatible migrations.
9. Preserve approved reports and historical financial values.
10. Do not reset the database.

==================================================

Primary success condition:

A contractor should be able to configure its existing field paperwork, billing requirements, work-package documentation, photo requirements, and approval process without custom code. A foreman should then be able to complete the required workflow from a phone, including during poor connectivity, and submit a complete review-ready package without re-entering the same information across multiple forms.
