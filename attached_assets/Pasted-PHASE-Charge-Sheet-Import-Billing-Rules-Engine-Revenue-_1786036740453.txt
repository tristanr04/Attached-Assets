PHASE: Charge Sheet Import, Billing Rules Engine, Revenue-Leakage Detection, and Approval Workflow

Objective:

Turn the application into a company-configurable billing and field-production system that helps foremen complete paperwork faster while reducing missed, incorrect, or undercharged billable items.

The company must be able to upload or manually configure its own charge sheets, unit prices, labor charges, equipment charges, customer contracts, and billing rules.

The app must then use those company-specific rules to:

- Pre-fill daily reports
- Suggest expected billable items
- Calculate estimated charges
- Detect potentially missing charges
- Detect undercharging
- Flag conflicting selections
- Preserve a complete audit history
- Route reports through review and approval

Do not hard-code one contractor’s prices, customer terms, or billing rules.

Do not remove or break existing:

- Authentication
- Company onboarding
- Crews
- Projects
- Daily reports
- Labor entries
- Equipment entries
- Work-package templates
- Mobile layouts
- Existing permissions
- Existing database records

Before implementation:

1. Inspect the existing database and code.
2. Confirm which models already exist.
3. Extend existing models instead of duplicating them.
4. Create safe database migrations.
5. Preserve all current user and demo data.
6. Run the existing test suite before making changes.
7. Fix any existing blocking errors first.

9. REVENUE-LEAKAGE DETECTION
==================================================

Create a report validation system specifically designed to find potentially missed revenue.

Check for:

- Work selected without a billing code
- Equipment used without a charge
- Labor hours without a labor classification
- Overtime hours billed at regular rate
- Double-time hours billed at overtime or regular rate
- Storm work without storm rates
- Mobilization missing
- Demobilization missing
- Minimum quantity not met
- Required associated charge missing
- Pole replacement missing removal or disposal charge
- Transformer work missing associated installation charge
- Backyard equipment missing specialty-equipment charge
- Work quantity not matching selected template
- Material used without associated work item
- Duplicate charges
- Rate lower than the active contract rate
- Expired rate used
- Wrong customer charge sheet selected
- Incorrect unit type
- Manual price override below allowed threshold
- Required documentation missing

Classify issues as:

- Informational
- Warning
- High priority
- Submission blocker

Each issue should show:

- What may be wrong
- Why it was flagged
- Related item
- Expected rule
- Current value
- Suggested correction
- Estimated financial difference
- Whether supervisor approval is required

Do not automatically change final billing values without human review.

==================================================
10. UNDERCHARGE DETECTION
==================================================

Compare the calculated report against the applicable active charge sheet.

Flag cases where:

- The entered rate is below the contract rate
- The quantity is below a configured minimum
- A required multiplier was not applied
- Storm or emergency rates were omitted
- A customer-specific rate was not used
- The foreman selected an outdated billing code
- A manual override reduced the charge
- Required associated equipment or labor was omitted

Display:

- Current estimated billing
- Expected billing based on configured rules
- Difference
- Percentage difference
- Items causing the difference

Example:

Current estimated total: $8,420
Expected configured total: $9,180
Potential undercharge: $760

This must be labeled:

“Potential billing difference — requires review”

Do not claim the amount is guaranteed lost revenue.

- Supervisor approved

- Billing approved

Workflow:

1. Foreman completes the report.
2. The system runs billing and documentation validation.
3. Foreman resolves or acknowledges warnings.
4. Foreman submits.
5. Supervisor reviews work details.
6. Billing reviewer reviews charges.
7. Authorized approver approves final billing.
8. Report becomes locked except for authorized amendment.

Allow companies to configure which approval stages are required.

Example:

“Digger derrick hours entered as 4. Crew report shows 10 working hours. Please confirm.”
