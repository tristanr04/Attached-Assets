PHASE: Commercialization, SaaS Billing, Implementation Management, Compliance Readiness, Support Operations, and Production Launch

Objective:

Prepare Redline to operate as a secure, sellable, multi-tenant SaaS platform for real utility contractors.

This phase must build the commercial and operational systems required to:

- Sell Redline to contractor companies
- Configure company subscriptions
- Manage contracts and pilots
- Onboard new customers safely
- Control feature access by plan
- Track usage without exposing private operational data
- Provide customer support
- Manage implementation projects
- Monitor application health
- Respond to incidents
- Protect customer data
- Prepare for security and compliance reviews
- Support production releases
- Measure whether Redline saves time and prevents missed billing

Do not remove, replace, or break existing:

- Authentication
- Company isolation
- Multi-division structure
- Employees and qualifications
- Crews and scheduling
- Work orders
- Daily reports
- Labor
- Equipment
- Fleet
- Materials and inventory
- Charge sheets
- Billing rules
- Missing-charge detection
- Undercharge detection
- Production tracking
- Job costing
- Invoice preparation
- Change orders
- T&M tickets
- Custom forms
- Photos
- GPS
- Signatures
- Offline drafts
- Customer portal
- Pilot mode
- Enterprise permissions
- API architecture
- Integration architecture
- Audit history
- Existing customer or demo data

Before implementation:

1. Inspect the complete repository.
2. Review the database schema and all migrations.
3. Review the current authentication, tenancy, billing, permissions, audit, support, and deployment architecture.
4. Identify unfinished features, mocked integrations, unsafe assumptions, and duplicated systems.
5. Run all tests, type checks, linting, builds, and migration checks.
6. Record all existing failures.
7. Fix blocking bugs before adding new features.
8. Use safe, backward-compatible migrations.
9. Preserve all historical operational and financial records.
10. Do not reset the database.
11. Do not activate paid third-party services without explicit authorization.
12. Do not deploy automatically to production.

3. CONTROLLED SUPPORT ACCESS
==================================================

Create a secure support-access system.

When Redline staff need access to a tenant for troubleshooting:

- Require an authorized tenant request or documented emergency reason.
- Limit access to the minimum required scope.
- Set an expiration time.
- Record the support employee.
- Record the reason.
- Record the tenant.
- Record the approved scope.
- Record every action performed.
- Notify the tenant administrator when appropriate.
- Allow immediate revocation.
- Automatically expire access.

Support-access scopes may include:

- View configuration
- View report metadata
- View error logs
- Impersonate a user in read-only mode
- Edit configuration with approval
- Export diagnostic data

Do not allow silent permanent impersonation.

Do not reveal wages, internal costs, or private files unless explicitly included in the approved support scope.
